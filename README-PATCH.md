# CC GUI с правкой: отправка мимо очереди

Это копия исходников CC GUI (ветка `local/cmd-enter-send-now`, стоит на теге
автора `v1.2.0`) со своими правками. Собранное приложение лежит здесь:

```
src-tauri/target/release/bundle/macos/CC GUI.app
```

## Что делает правка

В приложении было одно действие отправки: пока агент отвечает, сообщение
вставало в очередь и уходило только после конца текущего ответа. Добавлены
два жеста:

| Клавиши | Что происходит |
|---|---|
| `⌘ + Enter` | текущий ответ прерывается, моё сообщение уходит следующим — то же, что кнопка «Send» на карточке в очереди |
| `⌃ + Enter` | сообщение вклинивается в идущий ответ, не прерывая агента (движок pi: он видит его после текущего шага с инструментами) |
| `Enter` | как было: отправить, а если агент занят — встать в очередь |
| `Shift + Enter` | перенос строки |

Очередь при этом не ломается: `⌘ + Enter` не отменяет уже стоящие в ней
сообщения — они уходят после. Оба жеста перечислены в окне «Горячие клавиши».

Ограничения:

* `⌃ + Enter` работает только с движком **pi** (у остальных нет канала, по
  которому можно передать сообщение в идущий ответ). Для других движков
  `⌃ + Enter` делает то же, что `⌘ + Enter`.
* У совсем нового чата, где сессия ещё не получила свой номер, вклинить тоже
  нельзя — сообщение уйдёт сразу, как по `⌘ + Enter`.

## Ограничение вкладок сессий

Каждое открытие сессии из левого списка добавляло вкладку в полосу вверху, а
закрыть вкладку можно было только руками — к 30.10.2026 в списке накопилось
496 вкладок, и все они восстанавливались при следующем запуске.

Теперь вкладок сессий держится не больше **двадцати**. Когда открывается
двадцать первая, самая старая (левая в полосе) закрывается сама. Никогда не
закрываются:

* та, что открыта сейчас;
* та, что отвечает прямо сейчас;
* та, что остановилась и ждёт человека (красная точка);
* черновик «Новый чат» — в нём может быть неотправленный текст;
* та, что стоит в разделённом экране: её панель исчезла бы вместе с вкладкой;
* та, которую держит плагин (режим беседы).

Если закрывать нечего — все оставшиеся под запретом, — список временно
остаётся длиннее двадцати: это лучше, чем закрыть то, с чем работают.
Слишком длинный список, сохранённый прежней сборкой, обрезается при запуске.

## Канал уведомлений для плагинов

Плагин может попросить приложение показать системное уведомление — команда
моста `plugin_notify` (право `notify`). Показывает его само приложение, тем же
кодом, что свои уведомления: отсюда общий выключатель «Уведомления», звук
системы и переход в сессию по клику. Пользуется этим наш плагин «Уведомления»
(сообщает о прогонах задач по расписанию).

Что добавлено: право `notify` в списке прав плагинов
(`packages/plugin-sdk/spec/permissions.json` — его же читает серверная часть),
разбор команды в `src/features/plugins/runtime/context.ts`, отправка в
`src/lib/notifications.ts` (`notifyFromPlugin`), подпись права в списке плагинов
и словарях подписей. В официальной сборке этой команды нет: плагин получит
отказ и напишет в консоль приложения.

## Свёрнутые размышления и вызовы инструментов

Кнопка в поле ввода — сразу слева от счётчика расхода контекста. Пока агент
работает, «что он думает» и «что он вызвал» держатся свёрнутыми в одну строку и
не раскрываются сами — ни во время работы, ни после неё. Раскрыть один блок
можно щелчком по его строке, и он останется открытым.

Положение кнопки — своё у каждого проекта: в одном репозитории хочется видеть
ход работы, в другом тишина. По умолчанию свёрнуто везде; кнопка запоминает
исключения и переживает перезапуск.

Как выглядит: серая иконка слева от процентов контекста (тусклая — свёрнуто,
светлее — этот проект показывает блоки по ходу работы), подпись при наведении.

Что при этом не меняется: настройка «Складывать размышление по завершении»
(Настройки → Общие → Поведение) продолжает работать как работала — но видна
она только у проектов, где кнопка снята: там блоки раскрываются по ходу, а по
концу ответа складываются по этой настройке.

## Задачи и списки дел — одной колонкой в правой панели

Плагин может попросить, чтобы его вкладка стояла не отдельной колонкой, а
вместе с другой: `ctx.ui.registerPanelTab({ ..., stack: "имя колонки" })`. Вкладки
с одним именем рисуются в одной колонке, друг над другом, в порядке вкладок, а
между парами появляется разделитель — тянется мышью вверх и вниз, положение
помнится по колонке (`localStorage`, ключ `ccgui-next.panelStack.<имя>`).

Значок в полосе вкладок при этом остаётся только у первой вкладки колонки:
остальные достижимы самой колонкой, поэтому всё, что вкладка показывала на
значке (число, точку), она должна показывать внутри своей половины. Так у наших
плагинов: сверху список задач, снизу списки дел, а число несделанных пунктов
переехало из значка в шапку списков дел («Todo · 3»).

Половину нельзя спрятать совсем: у каждой остаётся не меньше 96 точек высоты.
Вкладка, объявленная в колонке одна (соседний плагин выключен), ведёт себя как
обычная — со своим значком и полной высотой панели.

## Обзор проекта в колонке чата

Клик по **названию** папки в левом списке открывает в колонке чата страницу
проекта — одним взглядом видно, что за проект и чем он занят, без открытия
сессий. Раскрыть или свернуть список сессий можно стрелкой сразу после названия
(она поворачивается, когда список раскрыт) либо значком-папкой слева от
названия; два жеста друг другу не мешают.

Что на странице:

* **Правила проекта** — пункты из файла договорённостей (`operator.md`);
* **Договорённости и разборы** — файлы памяти проекта с их описаниями;
* **Дела и расписания** — один блок в две колонки: слева списки дел по этому
  проекту, справа задачи по расписанию с ближайшим временем;
* **Навыки проекта** — только то, что лежит в папках навыков самого проекта;
  если своих нет — блока нет вовсе (общий набор машины тут не показывается);
* **Репозитории** — ветка и состояние каждого, самым низом и только если
  хранилища есть.

Блоки тянутся за ручку в шапке (появляется при наведении) вверх и вниз; клик по
шапке сворачивает блок в одну строку. Порядок и свёрнутость помнятся отдельно по
каждому проекту.

Обзор открывается вкладкой в полосе сверху (с именем проекта) и переживает
перезапуск: проект, куда возвращаешься, уже стоит, а сессия не вытесняется —
они рядом. Списка сессий в обзоре пока нет — так решено намеренно.

## Как пересобрать

```bash
./build-patched.sh
```

Скрипт отличается от штатного двумя вещами: подпись ставится своя (ad-hoc),
и не собираются артефакты обновления — для них нужен приватный ключ автора
приложения, а для подписи его сертификат. Оба шага приложение выполняет при
сборке, поэтому подменить их нельзя.

Сборка идёт 20–40 минут в первый раз (компилируется вся серверная часть),
дальше быстрее — уже собранное переиспользуется.

## Когда выйдет новая версия CC GUI

Теги берём у автора (`origin` — наш форк, свежих тегов там нет):

```bash
cd ~/Coding/ccgui-clean-ui/ccgui-patched
git fetch --tags upstream
pnpm install                        # автор добавляет зависимости — без этого падают проверки и сборка
git rebase --onto refs/tags/<новый-тег> refs/heads/v1.1.9 local/cmd-enter-send-now
./build-patched.sh
git push --force-with-lease origin local/cmd-enter-send-now
```

База — ветка автора `refs/heads/v1.1.9`, а не тег с тем же именем (тег — merge
коммит поверх неё). Последний перенос, 01.11.2026 на `v1.2.0`, дал конфликты в
семи местах — все от того, что автор дописал код рядом или переписал тот же
участок: разводятся сохранением обоих кусков, разбор в памяти проекта
(`.operator/specs/ccgui-host-patch.md`).

Правки — отдельные коммиты по темам (`git log --oneline` в этой папке): ввод
текста и отправка, красная точка «сессия ждёт человека», сессии плагинов вне
левого списка, ограничение вкладок, свёрнутые размышления и вызовы инструментов.
Переносятся на новую версию по одной, каждая отдельно.
## Про обновления внутри приложения

Собранная копия — обычное приложение с тем же именем и тем же внутренним
идентификатором, что и официальное, и настройки у них общие
(`~/.ccgui-next`). Но обновление, которое приложение предложит само, поставит
официальную сборку и затрёт правку. Обновлять — только через пересборку выше.
